# dsh-remote-ops v0.12.3 验收记录

## 范围与机制

修复 DSH 0.2.1 系列安装包时重载旧插件，旧插件卸载又等待安装结束造成的循环等待。新流程在必要时先等待任务结束，将当前实例及其状态移交到独立运行目录，再让宿主安装包；最终激活仍等待任务结束。卸载不再等待依赖自身卸载的安装 Promise。

安装 POST 返回 HTTP 202、`accepted` 与操作 ID；GET 查询进度。界面在明确的更新过程中允许短暂的接口中断，持续失败保留地址、阶段和响应摘要，并提供只查询、不重装的“刷新更新状态”。观察请求设定等待上限，业务操作不增加这一上限。安装 10 分钟未返回时显示结果未确认，不取消或重复执行安装。

本次仅修改插件、回归脚本和文档；未修改 Agent 或 DSH 宿主源码。运行时和测试服务均使用隔离目录，不替换用户正在使用的 3080 实例。

## 首次迁移与边界

v0.12.2 及更早版本正在执行的更新代码，无法被尚未加载的新包修复。先结束工作，使用同一用户、`DSH_HOME` 和 profile，通过 DSH 插件管理或 CLI 安装本版 tgz。CLI 安装后运行版本仍旧且页面可操作时，点击“重试应用已安装版本”；如果旧流程已经卡住，核对安装日志和磁盘版本，安装完成后重启一次。不要重复安装。之后从修复版发起的兼容更新使用新流程。

已保存配置和对话持久化保留；完整进程重启不会保留内存连接。测试没有访问用户另一台电脑、真实内网更新服务器或生产设备，不能据此确认其代理、证书、缓存或设备连接均正常。Windows Server 结果以本次 CI 实际记录为准。

正式 Release 包和候选包分别校验；发布后的下载摘要与独立安装验收在下节补记。
