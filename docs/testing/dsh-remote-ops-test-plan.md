# dsh-remote-ops 测试与回归门禁

## 目标

每次新增功能、修复问题或重构，都必须证明新代码没有破坏既有能力。测试分为四层：

1. **后端单元测试**：环境校验、分组规范化、凭据引用、错误信息、输出缓冲区、增量游标、长轮询取消。
2. **状态集成测试**：环境分组、环境文件、快捷命令分组/多行命令、凭据持久化和重新加载。
3. **客户端行为测试**：使用生产 `client.js` 中的实际函数验证 ConPTY 空屏清理、光标覆盖、滚屏和 SSH 命令解析。
4. **契约测试**：插件清单、所有 Agent 工具、API 路由、终端 CSS 约束、增量轮询、串行输入和发布脚本门禁。

## 固定命令

在 `integrations/dsh-remote-ops` 目录执行：

```powershell
npm ci
npm test
npm run check
```

`npm run check` 是唯一的发布门禁，包含语法检查和完整回归集。Release 脚本会再次调用该门禁，并且只有通过后才会打包、提交、打 Tag 和上传 Release。

## 功能覆盖矩阵

| 功能 | 自动化覆盖 | 关键断言 |
| --- | --- | --- |
| 环境新增、修改、分组、持久化 | 状态集成测试 | 重载后环境与分组仍存在，非法 id/端口/凭据引用被拒绝 |
| 快捷命令、多行命令、分组 | 状态集成测试 + 契约测试 | 多行命令原样保存，工具和动作仍注册 |
| SSH/本地终端输出 | 缓冲区单元测试 + 客户端行为测试 | 增量游标不重复，超限后有界，UTF-8 不截断，ConPTY 空屏不产生大片空白 |
| 终端滚动与末行 | 客户端行为 + 契约测试 + 3080 页面验收 | SFTP 返回恢复阅读位置或跟随末行；缩放不丢跟随；保留尺寸与滚动条约束 |
| Agent 与 UI 同流 | 注册工具/HTTP 路由行为测试 + 3080 真实模型验收 | local-cmd 可发送、读取、中断；发送等待新输出，不重复旧历史；续读与路由返回同一段流 |
| 输出分页与重启 | 后端和客户端行为测试 | 保留范围内按游标顺序分页、不拆 Unicode 代理对；同长度新流 reset；断续帧不能悄悄拼接 |
| 并发输入与等待 | 后端和客户端行为测试 | 输入锁定排队时的 session/owner；活动发送互斥；取消、退出释放等待；静默不报告命令完成 |
| Tab、控制键、SSH 命令 | 契约测试 + SSH 解析行为测试 | 解析 host/user/port/key，保留交互输入路径 |
| 多 SSH、批量命令、Agent 工具 | 工具契约测试 | 所有 `remote_terminal_*` 和 batch 工具持续存在 |
| SFTP | 工具契约测试 | list/read/write/mkdir/delete/rename 接口持续存在 |
| 输入接管 | 后端行为测试 | 人工输入阻止 Agent，交还后恢复；接管结束等待但不发送 Ctrl+C；宿主包装操作仍可停止等待 |
| 手动连接 | 状态行为测试 | 恢复已有宿主 owner 不发模型消息；复用唯一连接，多连接返回选择 |
| 连接与恢复 | 后端 + 客户端行为测试 | 环境名称和 sessionId 契约；无编号/备注；按 ID 释放、owner 隔离；断开保留目标、轮询退避 |
| 人工输入与工具回执 | 后端 + 客户端行为测试 | 不要求窗口身份，多个浏览器可输入/交还；人工阻止 Agent、流替换拒绝旧输入；UI 不产生工具回执 |
| 独立命令 | 子进程/SSH 通道行为 + 状态测试 | 真实非零退出、stdout/stderr、UTF-8 有界截断、超时取消 unknown、owner/并发隔离、不写 PTY |
| 文件传输 | 真实临时文件 + 路由测试 | >2 MiB 逐字节一致、目录层次、冲突、取消、排队取消、暂存清理、owner 隔离和自身覆盖拒绝 |
| 文件恢复与偏好 | 真实临时文件 + 客户端行为测试 | 重试只处理剩余项、覆盖预览只读、匹配目录刷新、定位保留排序、不存旧列表/勾选 |
| 浏览器传输 | HTTP 契约 + 流测试 | POST streaming 上传、GET buffered 请求/流式响应；不能给 GET 附加请求 body |
| 下载表示 | HTTP 路由与流测试 + 真实宿主 | no-transform、原始 Content-Length、逐字节一致，真实下载另检查压缩桥警告 |
| 全屏终端 | 生产 VT 模型 + 真实宿主 | 字符集选择不打印残留、备用屏/滚动区域/光标可见性、top/vim 网格及 shell 恢复 |
| 终端偏好与粘贴 | 生产客户端逻辑测试 | 宽字符定位、偏好范围、粘贴锁定 owner/终端、搜索匹配 |
| 诊断 | 白名单/错误链测试 | 保留阶段和原始 cause，导出不含终端正文/凭据 |
| 更新和发布 | 契约测试 + Release 脚本 | Release 前必须执行 `npm run check` |

## 3080 页面验收

自动化回归通过后，在有 DSH Web profile 的开发机上执行一次页面验收：

1. 打开 Remote Ops，确认插件版本和本地 CMD 显示。
2. 输入短命令，确认输出、最后提示符和光标行完整。
3. 连续输出至少 200 行，确认竖向滚动条可拖动、末行可见、底部自动跟随。
4. 向上滚动后继续输出，确认阅读位置不被抢回；滚到底部后确认自动跟随恢复。
5. 打开环境抽屉、快捷命令、SFTP 和诊断面板，确认终端区域没有被挤出或覆盖。
6. 在历史阅读位置打开并关闭 SFTP，核对 scrollTop；在末尾重复并缩放到窄屏，确认末行跟随。新输出按钮应回到底部。
7. 实际执行一条无副作用的快捷回显命令，验证输入目标和显示结果；清理验收创建的数据。
8. 真实模型调用 `remote_terminal_send`，随后用 `nextOffset` 和 `streamId` 调用 `remote_terminal_read`。检查展开的工具入参和结果，不以模型总结代替证据。
9. 区分插件 `local-cmd` 与宿主内置 shell；明确记录真实 SSH、SFTP 列目录、文件传输、操作系统输入法哪些已验证，哪些未验证。
10. 人工输入后让真实模型尝试写入，确认 `TERMINAL_MANUAL_CONTROL`；交还后发送/续读，分别验证停止等待、Ctrl+C 和释放连接。
11. 双侧独立选位置，浏览器上传大于 2 MiB 的临时文件，经 SFTP 复制/下载校验字节；同名、取消、目录和多选分别记录证据；只清理本次创建的临时文件。
12. 编辑快捷命令并核对目标，取消预览不能写终端；检查搜索、字号/换行持久化、诊断导出预览和窄屏布局。
13. 同环境打开三连接，恢复环境名称展示且无备注入口，按 sessionId 核对选择和释放中间连接，第四条连接被拒绝；退出当前 SSH 后保留末次输出、禁止输入，显式重连不重复命令。
14. 同一个 Harness 会话打开两个浏览器窗口，两边可直接人工输入且任一窗口可交还 Agent，不出现跨窗口接管/只读限制；人工与 Agent 协调保持。不要把两个窗口写成两台物理设备，也不要宣称同时输入不会交错。
15. 工具回执按 owner/stream 隔离，显示实际返回时间/范围；UI 读取不能生成工具回执，流重建后不能沿用旧回执。
16. 多文件中途冲突后重试，已完成项不重传；检查逐项结果、自动刷新、定位和覆盖预览。切换面板/会话后核对路径、排序、滚动、书签，不恢复旧目录缓存或勾选。
17. 独立 CMD/SSH 命令分别返回非零退出码、中文 stdout/stderr，不能污染 PTY；取消、超时和无退出消息保持 unknown。真实模型必须使用新工具核对原始结果。
18. 真实 top/vim 进入退出、字符集控制序列、备用屏恢复、长行和桌面/窄屏布局。固定 PTY 尺寸与视觉换行分别记录，不能声称宿主支持运行时 resize。

该页面验收属于 DSH 宿主能力验证，不在插件包中引入浏览器运行时依赖；页面验收结果应记录在对应 Release 说明中。

## 变更规则

- 新功能必须先补充对应测试，再修改实现。
- 修复过的缺陷必须保留一个回归用例，防止再次出现。
- 测试失败时不得直接发布；必须保留失败日志和失败用例名称。
- 若功能需要真实 SSH、SFTP 或 DSH 宿主才能验证，除自动化测试外必须执行 3080 页面验收。
