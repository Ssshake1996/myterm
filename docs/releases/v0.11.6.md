# myterm v0.11.6

发布日期：2026-09-02

本版本针对兼容网关在 HTTP 200 SSE 中返回业务错误、DeepSeek Harness 最终误报“模型返回空内容”的场景，补全请求结构诊断与原始错误传播。该版本不猜测、不删除模型请求参数；内网验证日志将用于准确定位被网关拒绝的字段。

## Provider 业务错误识别

- 识别 HTTP 200 SSE 事件顶层或 `error` 对象中的 `error_code`、`error_msg`、`code` 和 `message`。
- 业务错误不再作为 `[DONE]` 或空 completion 交给 Harness，而是以 Harness 原生 `LlmError` 终止当前调用。
- ACP 错误保留 Provider 原始错误码和原始消息，例如 `InferHub.001001005.400`，避免再次概括成 `model returned a completed response with no content`。
- Provider 业务错误使用独立诊断阶段 `chat_completions_provider_error`，便于 AI 和用户从日志中直接定位失败位置。

## 脱敏请求结构诊断

- 每次 Chat Completions 请求生成递增序号，并记录请求字节数、顶层字段、扩展字段、流式选项、推理参数和消息结构。
- 记录工具数量、工具名称和参数 Schema 的结构统计，用于判断内网网关是否拒绝工具调用或特定扩展字段。
- 不记录 system prompt、用户输入、消息正文、工具描述正文或 API Key；消息和工具文本只保留类型、数量与字符数。
- HTTP 非成功响应、内容类型不兼容、空流和 Provider 业务错误统一携带同一份请求结构摘要。

## 回归验证

- SSE 单元测试扩展为 11 个场景，覆盖用户提供的 `InferHub.001001005.400` HTTP 200 业务错误格式。
- 端到端兼容测试同时验证正常 ACP → Harness → Chat Completions 响应和 Provider 业务错误传播。
- 回归测试确认诊断日志包含请求与工具结构，但不包含测试用户提示词。
- 保留已有 SSE 分块、`[DONE]` 修复、reasoning 字段和完整 message 兼容能力。
