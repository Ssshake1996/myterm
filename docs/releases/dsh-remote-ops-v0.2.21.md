# dsh-remote-ops v0.2.21

按用户确认，仅回退 v0.2.20 中的两项增强，不撤销其他功能。

## 变更

- 取消浏览器窗口级输入所有权：不再传递/要求 clientId，不再显示另一窗口只读或窗口接管。多个窗口共享人工输入状态，任一窗口可交还 Agent。
- 取消稳定连接编号、连接备注及修改备注入口，终端标签、目标选择和独立命令结果恢复环境名称。
- 保留人工与 Agent 的输入协调、输入队列目标/owner/streamId 校验、过期流拒绝、连接选择/指定释放、每会话每环境最多 3 条连接。
- 保留断开输出与显式重连、工具回执、文件传输/重试/路径工作区、独立命令和 VT 修复。不增加依赖，不做旧数据迁移。

多个窗口同时输入可能交错；本次按要求移除窗口锁，不承诺多用户协同编辑。

## 自动化验证

先增加回归并确认旧实现失败，再修改实现。覆盖无窗口身份的人工输入/交还、人工占用拒绝 Agent、旧 streamId 拒绝、已注册工具和 HTTP 路由、环境名称快照、按精确 sessionId 选择/释放以及 3 连接上限。

`npm run check` 通过：50 项后端/状态/传输/路由/独立命令、22 项客户端行为、7 项契约及烟测。fake 宿主测试不代表真实模型、SSH 或 SFTP 成功。

## 3080 开发验收

- 同一浏览器上下文的两个独立页面均可直接输入，互相看到实际 CMD 回显；另一页面交还 Agent 后，首页面显示输入空闲。输入 HTTP 请求无 clientId，仍含 streamId。
- 真实模型在人工状态下调用 send，原始结果为 `Error: TERMINAL_MANUAL_CONTROL: User is editing this terminal; wait for them to release input control`；交还后仅发送一次 `echo AGENT021-OK`，游标 17647→17796，read 从 17796 返回空输出且游标不变。已展开原始工具输入/输出核对，UI 显示相同回显及实际回执；PTY completion 仍为 unknown。
- 保存环境真实 SSH 建立 3 条 PTY，第四条以 `REMOTE_SESSION_LIMIT` 拒绝。标签只显示环境名称，无连接备注入口；连接选择器进入 pty-2，UI 释放后仅剩 pty-1/pty-3，随后清理测试连接。
- 真实 SFTP 列出远端目录；本地 CMD 240 行输出、历史阅读位置、SFTP 往返、复制、快捷命令回显通过，临时快捷命令已清理。
- 桌面和 390px 窄屏无插件横向溢出，页面未捕获异常为零。

未验证两个物理客户端、OS 输入法候选提交和不同 SSH 主机互传；本轮没有重做文件上传下载字节校验或 top/vim 验收。3080 只是开发环境，不能代替另一台电脑的事实。

## 安装

Release 包：`dsh-remote-ops-v0.2.21.tgz`；校验文件：`SHA256SUMS-dsh-remote-ops-v0.2.21.txt`。安装后重启 DSH，并刷新旧浏览器页面以加载新客户端。
