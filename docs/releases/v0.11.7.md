# myterm v0.11.7

发布日期：2026-09-02

本版本根据 v0.11.6 内网诊断日志修复兼容网关拒绝 Agent 请求的问题。日志确认官方 DeepSeek Harness Provider 在未配置模型输出上限时会注入 `max_tokens: 256000`；普通模型测试不携带该字段，因此测试成功，而带完整工具集的 Agent 请求被网关以 `InferHub.001001005.400` 拒绝。

## Provider 默认输出上限

- 未显式配置最大输出 Token 时，发送边界会移除 Harness 继承的固定 `max_tokens`，由目标 Provider 使用自身默认输出上限。
- 保留 DeepSeek Harness Agent 循环、上下文、审批和全部工具，不删除或降级 SSH、CLI、SFTP、Skill、Goal、MCP 与本地工具。
- 显式配置最大输出 Token 时，数值会通过官方 Provider 模型配置进入 Harness，并原样发送给目标服务。
- 请求诊断增加 `provider_default` / `explicit` 策略及被移除的继承值，方便后续日志直接验证实际行为。

## 模型容量配置

- 每个主模型和备用模型增加折叠的“高级模型限制”。
- “上下文窗口”用于 DeepSeek Harness 的上下文规划与自动压缩阈值计算。
- “最大输出 Token”只控制 Provider 输出上限，不再与上下文窗口混用。
- 两项均可留空；最大输出 Token 不得超过已配置的上下文窗口，前端和后端均执行校验。
- “测试模型”在显式配置输出上限时使用相同值，避免设置测试与 Agent 行为不一致。

## 诊断与验证

- 工具诊断从逐个冗长对象改为工具名称和 Schema 汇总，避免大量工具导致错误日志中途截断。
- 请求策略单元测试覆盖 Provider 默认、显式上限和不可解析请求三种场景。
- ACP → Harness → 模拟 Provider 端到端测试确认实际请求不再包含继承的 `max_tokens: 256000`，并确认工具数组仍完整存在。
- 保留 HTTP 200 SSE 业务错误识别和 `InferHub` 原始错误码传播。
