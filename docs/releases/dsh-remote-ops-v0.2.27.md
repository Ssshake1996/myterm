# dsh-remote-ops v0.2.27

v0.2.26 安装在提供 `pluginNavigation` 管理服务的 DSH 中时，可能没有可直接打开 Remote Ops 的左侧按钮：旧版错误地将管理服务存在视为导航已注册。本版改为注册原生左侧入口与主工作区，仅在实际入口可用后隐藏兼容按钮。

本版基于 `dsh-remote-ops-v0.2.26`（`671fc80`），保留其交互脚本、终端尺寸、分层状态实现和禁止自动回答 y/n 的行为。此前 `main` 停在 v0.2.23、本地 v0.2.27 候选未发布；本轮同时同步仓库首页、发布包中的中英 README 和正式版本，避免其他电脑继续下载旧包。

## 变更

- 左侧入口使用 DSH 原生 `sidebar.panellist` 与 `main`，稳定 ID 为 `dsh-remote-ops`，显示名为 `Remote Ops`，排序 40。单色终端图标响应宿主尺寸和选中态。
- 原生主工作区从宿主 `useSessions` 读取 `retainedBy.mainView`，保持 SSH owner 边界，无当前会话仍可操作本地 CMD。主面板打开时不渲染旧右侧终端，避免重复请求。
- 原生插槽可用时隐藏 footer 和旧 guide 入口；不再凭 `pluginNavigation` 服务存在就隐藏按钮。旧宿主保留兼容入口，启动重试卸载后取消，最后一次成功不再误报失败。
- 恢复 Ctrl+V / Ctrl+Shift+V 原生粘贴及多行确认流程，保留 Ctrl+C 中断。
- 连接操作在会话切换后丢弃过期结果、错误和 busy 更新，避免旧连接响应改写新会话的终端选择。
- 面板切换后保留按 owner/终端/输出流隔离的未提交输入标记，防止快捷命令与 PTY 中的半条输入拼接；只保存布尔标记，不保存输入文本。普通输入和粘贴在服务器确认后才更新标记，失败、卸载及旧请求响应保守保留保护；粘贴发送中禁止普通输入和快捷命令并发。
- 保留包名 `@dsh/remote-ops`、tab ID、工具与存储格式，没有新增运行时依赖。包内显式包含中英导航 locale。
- 修复现有 E2E runner 在 Windows 把 URL.pathname 当文件路径而产生 `F:\F:\...` 的问题，改用 `fileURLToPath`。
- 四份中英 README 的安装、入口、升级和发布说明同步到 v0.2.27。发布门禁检查 README 命令中的版本，发布提交集合包含仓库首页，防止文档继续指向旧安装包。
- 发布包文本统一 LF，避免 Windows 工作区与 GitHub Linux 打包的换行差异影响包摘要校验。

## 安装与兼容

从本 Release 下载 `dsh-remote-ops-v0.2.27.tgz`，使用启动 DSH 的同一系统用户、`DSH_HOME` 和 profile 安装：

```powershell
dsh plugin --profile web add .\dsh-remote-ops-v0.2.27.tgz
dsh web
```

升级前先停止原有 DSH，安装后重新启动并刷新浏览器。界面必须显示 `v0.2.27`；DSH `0.2.0-rc.2` 使用左侧 `Remote Ops` 入口进入主工作区。缺少原生面板接口的宿主保留底部按钮和右侧面板作为降级入口，旧版本或定制 DSH 仍需实际验证。该按钮的显示不再依赖另一款导航插件。

## 验证边界

- 页面刷新后 DSH 回到对话页，不自动恢复全局 Remote Ops 主面板；再次点击可进入，入口不会重复。
- 切离运维主面板会结束组件内正在等待的独立命令，并取消浏览器上传；这是现有组件卸载策略。上传离开提示和后台传输列为后续改进。
- 本轮未验证真实 SSH、真实远端 SFTP、模型调用、物理多客户端、操作系统输入法，也未声称所有旧宿主版本兼容。

## 后续交互改进

1. **SFTP 上传切换保护（优先）**：浏览器上传由 SFTP 组件持有，切回终端会卸载组件并取消上传。建议先提供明确的离开确认与取消反馈；若要后台继续上传，需要将任务生命周期移至面板层，再验证断线、取消与重入。
2. **SFTP 完成任务刷新合并**：首次读取历史完成任务时，同目录的每项任务都会触发目录请求。已有三个完成任务、两个匹配面板的模拟行为复现产生八次目录读取。建议首轮只建立任务基线，后续每轮按面板合并一次刷新，再覆盖滚动和选中状态。

以上两项暂未改动；需要单独验证文件传输与任务生命周期，避免扩大本轮导航和小范围输入修复。
