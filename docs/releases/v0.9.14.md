# myterm v0.9.14

本版本收口 AI 配置管理、模型连通性验证、终端横向滚动和服务器环境配置存储，重点解决“旧 AI 配置无法清理”“模型列表与真实推理混为一次测试”“Windows WebView 横向滚动条不可见/不可拖动”和“服务器环境混在主配置文件”四类问题。

## 主要变化

- AI 服务设置新增统一的“已保存配置”区域；非当前配置可删除，当前配置必须先在 Agent 面板切换，删除配置不会删除对话历史。
- 将 AI 验证拆成两个独立动作：
  - “获取模型”请求模型列表端点并展示完整模型对象、Endpoint 和原始 JSON。
  - “测试模型”使用选定的已启用模型和可编辑提示词（默认 `hi`）发起真实 Chat Completions 请求，展示模型正文、实际模型、耗时、Endpoint、原始 JSON 和完整失败诊断。
- 自动换行关闭时使用 myterm 自有的显式横向滚动控件，并与终端 `scrollLeft` 双向同步，不再依赖 Windows WebView 自动隐藏的原生横向滚动条。
- 服务器环境信息从 `config.json` 拆分到顶层 `environments/` 目录，一个分组对应一个 `<分组名>.environments.json` 文件。
- 新建或编辑会话时即时校验 Windows 非法字符、控制字符、首尾空白、结尾句点和保留设备名；非法名称会显示具体原因并禁用保存。
- v0.9.14 首次启动会把旧 `config.json.profiles` 自动迁移到分组文件，非法旧分组名自动替换为安全名称并提示迁移结果；该兼容迁移代码仅保留一个版本，计划在 v0.9.15 删除。
- 环境文件写入采用临时文件原子替换；大小写冲突不会覆盖已有 Windows 文件，磁盘写入失败也不会污染内存中的配置列表。

## 验证范围

- 前端组件回归覆盖 AI 模型获取、真实模型测试结果、非当前配置删除、非法环境分组和终端换行切换。
- Rust 回归覆盖环境文件 CRUD、旧配置一次性迁移、非法/保留名称、Windows 大小写冲突、AI 返回正文解析和完整错误诊断。
- 本地浏览器实测确认：显式横向滚动控件可见，设为 `1200` 时终端实际 `scrollLeft` 同步到约 `1199.94`；AI 设置同时显示两个测试动作和删除入口；`prod/db` 即时阻止保存；控制台无错误。
- 完整前端、Rust、生产构建、分发审计和运行时内存/句柄采样由标准发布脚本执行。
