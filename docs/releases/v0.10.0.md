# myterm v0.10.0

发布日期：2026-08-29

v0.10.0 是新的大版本起点。本版重构 Chat Completions 下的大结果与上下文压缩路径，目标是在不引入专用压缩模型、不截断原始证据、也不把软件扩展成臃肿编排平台的前提下，降低长时间 Linux 运维对话中重复发送查询结果的成本。

## 主要变化

- 工具结果原文与模型消息分离：超过 8 KiB 的终端、文件、MCP 和查询结果保存为不可变 artifact，记录字节数与 SHA-256；小结果继续使用原生工具消息。
- 新增版本化 Result Capsule。模型上下文保留 `resultId`、工具状态、任务相关的来源事实与精确摘录，不使用任意头尾截断，也不把本地 Reducer 的输出伪装成完整原文。
- 新增 Core 内置只读工具 `result_read`，支持对已保存结果做字面行搜索或 UTF-8 安全分页。恢复证据不会重新执行 SSH、MCP 或其他可能产生副作用的工具。
- 本地压缩升级为 Checkpoint v2：每次只处理上一 checkpoint 和尚未压缩的新 tail；模型选择用户纠正、事实和结果引用，宿主从持久化来源校验并注入精确文本、CLI 命令与 Evidence。
- 已完成且无后续价值的查询噪声可以从 checkpoint 删除；仍可能需要复查的原始结果通过 `resultRefs` 保留。
- Token 预算新增系统 Prompt、工具 Schema、协议开销和输出预留。压缩失败时把上一轮严格 JSON 校验错误反馈给下一次重试，初次请求加 3 次重试都失败后才终止 Turn。
- 默认 Agent 系统 Prompt 增加 Result Capsule / `result_read` 使用契约，明确不得为恢复输出而重跑有副作用工具。
- 删除 v0.9.14 只保留一版的旧 `config.json.profiles` 环境迁移字段、迁移 IPC、前端提示和专用测试；分组环境文件、严格文件名校验与原子写入继续保留。
- 固化 Windows 冷缓存构建配置，直接使用 `aws-lc-sys` 随 crate 提供的 x64 预编译汇编对象；正式构建无需额外安装 NASM，也不会退化为无汇编 TLS。

## 兼容性与取舍

- 不需要新增压缩模型；压缩仍使用当前配置模型，本地 Reducer 是确定性、无网络的结果投影层。
- 现有 Responses / Chat Completions 自动回退、多模型配置、SSH、MCP、Skill 和权限模式保持兼容。
- SQLite 会自动创建 `tool_results` 表。原始结果文件保存在 Agent 状态目录，删除对应对话时同步清理。
- 首次遇到信息不足的 Capsule 时可能增加一次本地 `result_read`，换取后续模型请求不再重复携带完整大结果。
