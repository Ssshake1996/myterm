# myterm v0.11.1

发布日期：2026-09-01

本版本将 Agent 运行时彻底替换为官方 DeepSeek Harness ACP，同时保留 myterm 的 SSH、交互式 CLI、SFTP、多 SSH、权限和外部 MCP 能力。旧 `dsh-codex-agent` 与裁剪 Codex Core 已从产品构建中删除，不保留开发阶段兼容路径。

## 官方 DeepSeek Harness

- 固定使用官方 DeepSeek Harness `0.1.2-alpha.3` 与 ACP SDK `1.4.0`，由 Harness 负责 Agent Loop、持久 Session、Goal、上下文压缩、本地 Shell/文件工具和 Skill。
- Rust 宿主通过 ACP v1 NDJSON 启动、监管和恢复 Harness Session，支持取消、权限请求、工具事件、模型路由失败详情和响应后继续。
- Harness 按需启动；空闲时不常驻 Agent Node 进程。安装包携带私有 Node，最终用户无需安装 Node.js。
- AI 设置和 Agent 面板统一显示 DeepSeek Harness、ACP、本地工具、Host MCP、Goal、Skill 与运行状态，不再保留旧 Core 的循环步数等配置。

## SSH、CLI、SFTP 与多 SSH 工具

- myterm 为每次 Agent 运行启动仅监听 `127.0.0.1`、随机路径且随机 Bearer 保护的 Streamable HTTP Host MCP。
- Host MCP 保留会话目录、自动连接、终端上下文、完整 CLI 命令事务、终端编辑、远程执行、后台 Job、SFTP 文件工具、主机事实、Runbook 和多 SSH 等待能力。
- 本地计算机操作由 Harness 自带工具负责；Host MCP 的目录工具只允许 `remote` scope，Schema 和执行入口均拒绝本地越界。
- 外部 stdio/streamable-http MCP 继续由 myterm CapabilityProvider 管理，Agent 可读取连接状态、完整工具信息、Resources、Prompts 和原始错误详情。

## Provider 与协议验证

- OpenAI 兼容 Base URL 会规范化到 `/v1`，Bearer 和原始 Authorization 两种认证模式继续支持。
- ACP 错误保留阶段、错误码、Harness 原始错误和脱敏后的 sidecar stderr，不再用笼统文案替代真实错误。
- 已使用保存的 Provider 完成非流式 Chat Completions、普通 SSE、工具调用 SSE 和完整 Harness 工具 Turn 实测；普通流返回 `finish_reason=stop`，工具调用流返回 `finish_reason=tool_calls`。
- 模型路由仍支持主模型和备用模型，单条路由失败后按配置继续尝试下一条路由。

## 生命周期、构建与维护

- Agent 关闭时取消活动 Turn/Job、关闭 MCP、等待资源释放并显式关闭 SQLite，修复 Windows 临时数据库被当前进程占用的问题。
- 新增固定 Harness runtime/profile 检查、ACP smoke、网络边界审计和本地/远程工具边界测试。
- 标准构建按 Harness lockfile 准备生产依赖与私有 Node，再生成 NSIS 安装器和便携 ZIP；制品检查确认必需运行时文件存在。
- 更新中英文 README、用户说明书、Agent 架构、Linux Agent 计划/说明书、构建流程和开发经验记录。

## 升级说明

- Windows 安装器支持覆盖安装；服务器、环境分组、快捷命令、AI 配置、Skill、MCP 和系统凭据引用继续保留。
- Agent 内核与旧版本不兼容，旧 Core 的私有 Session/循环配置不会迁移；当前仍处于开发阶段，以新的 Harness Session 为准。
- 便携版请替换完整目录，不要只覆盖 `myterm.exe`，因为 Harness runtime 和私有 Node 位于 `resources` 目录。
