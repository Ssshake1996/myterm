# myterm v0.9.9

## Agent 请求合并与 CLI 执行

- 新增 `cli_execute` 原子执行器：在会话输入锁内读取真实 xterm 光标行，只发送完整目标命令的缺失后缀，并返回本次命令的输出增量、完成原因和现场快照。
- 新增 `cli_execute_batch`：一次工具调用串行执行 1-8 条互不依赖的已知 CLI 命令；遇到交互或超时立即停止，依赖前序结果的命令不得批处理。
- `terminal_context` 单次读取上限从 8 KiB 提升到 64 KiB，继续支持 `offset/nextOffset/eof`，减少长输出被切成大量短小模型往返。
- Codex Core 可并发执行同一模型响应内由宿主明确标记为安全的独立只读工具；有副作用、需要审批或存在依赖的调用保持串行。
- Agent 时间线新增本轮模型请求数、工具调用数和 Token 用量，便于发现低效循环。

## MCP Capability Registry 与证据链

- stdio 与 streamable-http MCP 工具统一进入任务级 Capability Registry，保留稳定 ID、Provider、Transport、title、description、Input/Output Schema 和 annotations。
- 移除固定的“48 个工具”切换分支。小目录直接暴露；大目录按任务相关度和 Schema 字节预算选择能力，并始终保留 `capability_search`。
- 新增 `capability_invoke` 与 `capability_invoke_batch`；调用参数按 Input Schema 校验，服务声明 Output Schema 时校验 `structuredContent`。
- MCP `isError=true` 保持为真实工具失败。完整原始返回保存为任务 Evidence artifact，长内容通过 `evidence_read` 分段读取。
- 根据 MCP 结果生成产品 CLI 命令时使用 `evidence_refs` 关联来源；不存在或跨任务的证据引用会被宿主拒绝。
- MCP 设置详情增加 Capability ID、标题、Output Schema 和 annotations 展示。

## 方案取舍

- 优点：减少“一次请求只做一个小动作”的往返；MCP 查询、命令合成和 CLI 执行形成可追溯证据链；新增能力复用统一 descriptor，不继续扩大固定 Agent 分支。
- 代价：只并发宿主明确认定的只读工具，不把第三方 annotation 当作安全证明；复杂依赖链仍需要模型逐步判断。未知设备提示符可能使用静默兜底或超时，不通过猜测强行判定成功。
- 轻量边界：不引入代码解释器、通用 DAG、长期记忆、常驻 Agent 服务或新的多 Agent 编排层。
