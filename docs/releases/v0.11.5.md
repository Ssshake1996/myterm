# myterm v0.11.5

发布日期：2026-09-02

本版本继续修复模型测试成功、DeepSeek Harness Agent 却以 HTTP 200 返回 `model returned a completed response with no content` 的兼容问题，并改善 Harness 原始错误的结构与可读性。

## Chat Completions 流式兼容

- 保留 DeepSeek Harness 官方 Provider，不修改或分叉 Harness 核心。
- 在流式边界规范化兼容网关常见的 `delta.reasoning` 字段，使其进入 Harness 原生 `reasoning_content` 内容块。
- 兼容网关在 SSE 中返回完整 `choices[].message` 而非 `choices[].delta` 的响应，将其转换为标准流式增量后再交给 Harness。
- 延续 v0.11.4 的 `[DONE]` 修复，并使用官方 `eventsource-parser` 处理任意网络分块、注释、CRLF 和 SSE 事件边界。
- SSE 解析缓冲设置 4 MiB 上限，避免异常网关持续发送不完整事件造成无界内存增长。

## 诊断与错误展示

- 当响应仍然没有可识别内容时，stderr 会记录事件数量、内容字符数、工具调用数、顶层字段、choice 字段、delta 字段以及脱敏后的首尾事件预览。
- 模型路由错误保持嵌套 JSON 结构，不再把 ACP 错误二次编码成大量转义字符。
- Agent 面板从结构化错误中提取阶段和 ACP 错误码，例如 `session/prompt · ACP -32603`，详情保持完整格式化 JSON。
- Harness 重试产生的连续相同 stderr 行会显示一次原文和额外重复次数，避免错误详情被重复文本淹没。

## 回归验证

- 9 个 SSE 协议场景覆盖标准流、CRLF、跨分块 `[DONE]`、不完整结束符、缺失结束符、正文包含 `[DONE]`、reasoning 别名、完整 message 和空响应诊断。
- 新增真实 ACP → DeepSeek Harness → 模拟 Chat Completions 网关端到端测试，验证兼容转换后单次请求即可正常 `end_turn` 并返回模型内容。
- Agent 前端测试验证结构化错误、URL 和原始 stderr 不会在 myterm 内被转换成 Markdown 链接。
