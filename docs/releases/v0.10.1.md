# myterm v0.10.1

发布日期：2026-08-29

本版把 Agent 上下文管理收敛为完全自适应策略，并修复删除模型后 Agent 下拉框错误显示“未配置模型”的问题。实现保持轻量：没有增加新服务、手工协议开关或常驻进程，能力状态继续复用现有 SQLite checkpoint 与本地日志。

## 修复

- Agent 与 AI 设置使用统一的有效模型规则：按启用状态、非空模型 ID 和角色优先级选择；删除主模型后自动提升第一个可用模型，不再出现界面显示未配置但后端仍可对话的不一致。
- Provider checkpoint 的 `through_seq` 仍持续保存，“不支持 Responses”能力按 Provider 指纹跨对话复用，且仅在上下文模式或能力状态真正变化时显示时间线事件，持久回退不再每一步或每个新对话重复提示。
- Provider 能力缓存加入 Base URL、模型和认证方式的 SHA-256 短指纹。配置变化会自动重新探测，且日志和 SQLite 不暴露原始 Endpoint 或模型值。

## 自适应上下文

- 删除 AI 设置中的上下文协议选择和 JSON `context_mode` 字段；配置 schema 升级到 v4，首次打开旧配置会自动清理该字段。
- 默认优先 Responses；明确不支持时跨对话持久使用 Chat Completions checkpoint + tail；瞬时故障只在当前请求回退，不污染长期能力判断。
- 本地 checkpoint、Result Capsule、三次压缩重试和多模型故障切换保持原有契约。

## 诊断与维护

- 安装版默认写入 INFO 级结构化 JSON 日志，`--debug` 提升为 DEBUG；记录稳定事件名、Provider 指纹、决策、错误阶段、错误码和原始错误详情，不记录 API Key。
- 日志按天滚动并保留 14 天，避免长期运行无限占用磁盘。
- Codex Core 为每次 Provider checkpoint 写入结构化 SQLite 审计事件，维护 AI 可联合时间线、JSON 日志和持久状态定位问题。
- 标准 `-RunRustTests` 发布流程新增 dsh-codex-core 独立测试，避免依赖 crate 的内核回归未被执行。

## 验证

- 前端覆盖无主模型时的 Agent 下拉框、自动提升主模型和无协议选择器。
- Rust 覆盖 Provider 状态去重、配置指纹失效、schema v4 清理、后端模型归一化和日志保留范围。
- 发布流程继续执行前端测试、Biome、生产构建、Rust 格式/检查/测试、Release 构建、分发审计与运行时内存/句柄采样。
