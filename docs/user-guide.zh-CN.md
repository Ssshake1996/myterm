# myterm 使用说明书

本说明书适用于 myterm 0.9.8。myterm 将服务器管理、SSH 与本地终端、SFTP、快捷命令和 dsh-codex-agent Linux 运维 Agent 放在同一个紧凑工作区中。

## 界面总览

- 最左侧活动栏用于打开会话侧栏、文件视图、AI Agent 和设置。
- 会话侧栏用于搜索、分组、新建、编辑、删除和连接服务器。
- 顶部标签栏用于切换、排序和关闭会话，最右侧问号按钮打开本说明书。
- 中央工作区显示终端或 SFTP 文件视图。
- 下方快捷命令库用于执行常用、部署和排查命令。
- 即使当前没有活动会话，快捷命令库也固定在工作区底部；服务器和会话区域独立占用上方空间。
- 右侧 Agent 面板显示任务、工具调用、审批、后台 Job 和最终答复。
- 底部状态栏显示连接、编码、SFTP、Agent 和版本状态。

## 首次使用

1. 从桌面快捷方式启动 myterm。
2. 点击左侧会话按钮，再点击“新建”。
3. 选择 SSH 或本地终端，填写名称和连接信息。
4. SSH 密码或私钥口令会保存到 Windows 凭据库，不写入普通配置文件。
5. 点击“保存并连接”打开第一个会话。

应用重启后，点击已保存服务器即可再次登录。服务器配置、主题、快捷命令、AI 配置引用、Skill 和 MCP 设置会持久化。

## 服务器与会话

### 新增 SSH 服务器

- 名称用于侧栏和标签显示，建议使用可识别的主机或业务名称。
- 分组支持使用 `/` 表示层级，例如 `生产环境/Web`。
- 环境用于权限风险判断，生产环境中的写操作会更严格。
- 默认 SSH 端口是 22，可按实际情况修改。
- 支持密码和私钥认证；敏感口令只保存到系统凭据库。
- 终端类型通常使用 `xterm-256color`。
- 连接失败时，终端遮罩会显示原始阶段、错误码和底层详情。详情文本可直接拖选，也可点击“复制错误”；“重新连接”是独立按钮，不会因为选择错误文本而误触发。

### 编辑和删除

- 点击服务器行右侧铅笔按钮编辑。
- 编辑时密码留空表示保留原有凭据，不会替换为空密码。
- 点击删除按钮后必须再次确认；删除配置时会同时清理对应凭据引用。
- 右键服务器行也可以进入编辑，但连接只使用单击，避免重复打开会话。

### 搜索和自动登录

搜索框会匹配服务器名称、分组、用户名和主机。连接成功后，后续启动可通过保存的配置和系统凭据自动登录，不需要把密码写入启动参数。

## 终端与标签

### 标签操作

- 单击标签切换活动会话。
- 拖动标签调整顺序。
- 点击标签上的关闭按钮断开该标签中的所有连接并移除工作区。
- 点击加号创建新的会话配置。

### 分屏操作

- 点击工作区右上角“向右分屏”按钮创建第二个终端。
- 拖动中间分隔条调整比例。
- 每个分屏标题栏都有关闭按钮，关闭后会断开对应连接。
- 分屏只有“存在”和“关闭”两种状态，不会保留临时隐藏的后台终端。

### 终端输入

终端支持常用控制序列、颜色、UTF-8 和窗口自适应。粘贴或执行未知命令前应先检查内容；使用 root 或生产服务器时应优先采用只读排查。

## 快捷命令

### 命令集

快捷命令按命令集分类。左侧命令集适合建立“常用”“部署”“排查”或具体业务分组，主区域只显示名称，以便在大量命令中快速扫描。

### 新建和编辑

- 点击快捷命令面板中的“新建”。
- 填写短而明确的名称、所属命令集和命令正文。
- 命令正文不会显示在紧凑列表中，但仍参与搜索并可在编辑器中查看。
- 可设置发送后是否自动回车。
- 编辑按钮位于每条命令右侧。

### 多行命令

一个按钮支持多行命令。保存时会保留行结构，执行时每一行按照终端回车语义发送。多行内容会按顺序执行，因此不要在未确认目标服务器时运行带副作用的脚本。

```bash
cd /opt/myapp
docker compose pull
docker compose up -d
```

### 导入快捷命令

- 点击搜索框右侧的导入图标，选择 myterm `.json` 或 Xshell `.qbl` 文件，文件最大 2 MB。
- Xshell `.qbl` 支持 UTF-16LE、UTF-16BE 和 UTF-8，兼容 Xshell 8 的 `Button_*` 字段以及旧版 `Type_/Label_/Text_/CR_` 字段。
- myterm 只导入 Xshell 的“发送字符串”动作；菜单、脚本、启动程序和发送文本文件等动作会显示在“不支持”数量中，不会转换为另一种行为。
- 预览会显示文件命令数、可导入数、完全重复、同名冲突、不支持项和目标命令集，确认前不会修改配置。
- “保留两者”是默认策略，同名不同内容会以“名称 (导入)”保存；“覆盖同名”会保留原条目的位置和 ID，只更新命令正文与自动回车设置。
- 完全相同的命令会自动跳过。整个导入结果一次性原子写入，不会留下只导入一部分的配置。

### 导出快捷命令

- 点击导出图标，选择“当前命令集”或“全部命令”，再导出 JSON。
- 文件使用 `myterm.quick-commands` 版本 1 格式，包含名称、命令集、正文、自动回车和顺序，不包含本机运行时 ID。
- 导出的 JSON 可在另一台 myterm 中预览并合并；它不是 Xshell `.qbl`，不能直接导回 Xshell。

### 面板空间

- 拖动面板顶部调整条改变高度。
- 点击明确标注的“收起”按钮关闭命令库正文。
- 收起后点击“展开”恢复之前的高度。
- 命令数量较多时使用搜索和命令集导航，不需要横向寻找按钮。

## SFTP 文件管理

只有活动 SSH 会话可使用远程文件视图。点击工作区工具栏中的“文件”进入 SFTP。

- 左右面板分别用于本地和远程目录。
- 首次打开时，本地窗格进入当前 Windows 用户目录，远程窗格进入 SSH 用户的登录目录。
- 两个窗格独立读取；一侧目录不存在或无权限时，另一侧仍可继续浏览，提示会标明“本地”或“远程”及具体原因。
- 双击目录进入，使用上级按钮返回。
- 刷新按钮重新读取当前路径，不会跳回初始目录。
- 普通点击只选择当前项；按住 `Ctrl` 点击可追加或取消单项，先选择起点再按住 `Shift` 点击终点可连续选择两者之间的全部项目。
- 两侧窗格底部显示选中数量；切换目录、刷新或切换服务器会清空当前选择与区间锚点。
- 上传和下载会把全部选中文件或目录加入传输队列，目录会递归传输；后端最多同时执行两个任务，其余任务保持排队。
- 新建目录不依赖选择；重命名只允许单个远程项目；删除支持一次确认后逐项递归执行，并报告成功数量和部分失败原因。
- 传输队列显示方向、名称、进度和状态，可取消未完成任务。
- 文件删除和覆盖具有实际副作用，执行前确认当前路径和服务器环境。

## 主题与常规设置

设置窗口的“字号”区域提供两组独立选项：

- “界面字号”提供小（90%）、标准（100%）、大（115%）、特大（130%）、150%、175% 和最大（200%）七档，控制侧栏、工具栏、面板和弹窗文字。高分辨率或远距离查看可从 150% 起逐级调整。
- “终端字号”提供 `12px` 到 `22px` 档位，只影响 SSH 和本地终端内容，不会改变终端连接。调整后立即重新适配终端列数和行数。
- 两项设置都会保存到应用配置，重启 myterm 后继续生效；配置失败会恢复到修改前的值。

### AI 认证方式

AI 服务设置中的“认证方式”决定请求头格式，API Key 本身仍只保存到操作系统凭据库：

- `Bearer Token`：发送 `Authorization: Bearer sk-xxxx`，默认兼容 OpenAI、DeepSeek 和大多数 OpenAI 兼容网关。
- `API Key`：发送 `Authorization: sk-xxxx`，适用于要求原始密钥值的网关。

测试连接、普通对话和 Agent 工具循环共享该配置。修改认证方式后点击“保存配置”，再使用“测试连接”验证；日志和 Agent 事件会继续脱敏，不显示密钥。

### 系统证书与内网 HTTPS

AI 测试连接、普通请求和 Agent 模型请求使用 Rustls，并从操作系统证书库加载受信任根证书。企业内网 CA、安全网关或 HTTPS 检查代理的根证书应由管理员安装到 Windows 的“受信任的根证书颁发机构”，不需要关闭证书校验，也不要把私有 CA 写入 myterm 配置。

myterm 在启动时创建 HTTPS 客户端并读取系统根证书。新安装或更新企业 CA 后应完全退出并重新打开 myterm，再执行“测试连接”。如果验证仍失败，详情区域会保留原始 TLS 传输错误和调用堆栈，便于区分根证书不受信任、证书过期、主机名不匹配和网络连接失败。

测试连接或 Agent 请求失败时，界面会先显示概括：失败位置和稳定错误码，例如“请求模型列表 · HTTP 401 Unauthorized”。点击“查看详情”后，才展开原始诊断、Endpoint、服务端响应体、传输错误、JSON 解析错误和调用堆栈；工具错误还会保留 stderr、退出码和超时状态。只会对 API Key/Token 脱敏，并限制诊断最多 16,000 个字符；超限会显示截断标记。界面不会把 401、超时或 MCP spawn 错误改写成推测性的原因。

### 多模型与 JSON 配置

AI 服务设置支持多个模型角色：

- 主模型：默认负责普通对话和 Agent 决策。
- 分析模型：用于后续高复杂度分析或作为第二候选模型。
- 备用模型：主模型请求失败时的兜底模型。

启用“失败时自动切换”后，后端会按主模型、分析模型、备用模型顺序尝试；每次 Agent 运行会在时间线显示实际选中的模型。前端保存的表单会转换为版本化 JSON，配置文件只保存模型、路由、提示词和凭据引用，不保存 API Key 原文。旧版本只有 `model` 字段的配置会在首次打开时自动迁移为 `models.primary`。

### 完整终端输出

Agent 不再按固定“最近 N 行”读取终端。`terminal_context` 返回 `offset`、`nextOffset`、`totalBytes`、`totalLines` 和 `eof`，模型可以连续读取直到 `eof=true`，因此大文件 `cat`、长日志和部署输出不会因为固定行数而读不全。远程命令的超长 stdout/stderr 会保存为 artifact，后台 Job 使用 `job_output` 按 offset 分页读取。

点击左下角设置按钮，可选择白色、护眼色或深色主题。主题会保存到配置，并同步更新终端、弹窗、快捷命令和 Agent 面板，不需要重新连接服务器。

在同一设置区域可选择终端配色模板：

- 石墨青金：深色背景下的暖色命令高亮，适合长时间运维。
- 森林护眼：低蓝光的绿色命令高亮，适合护眼主题和持续排查。
- 午夜高对比：蓝色高亮与正文形成更强区分，适合高分辨率或远距离阅读。

模板只改变本地终端的显示：用户输入的命令使用模板高亮色，服务器回显使用终端正文色，不会修改服务器 shell 或命令输出内容。快捷命令和 Agent 回填命令也会沿用当前模板。

设置页面还显示版本、内核提交和运行模式。便携模式通过启动参数 `--portable` 或程序旁的 `portable.flag` 启用。

## AI 配置

打开 Agent 面板右上角的 AI 服务设置，填写 OpenAI 兼容服务的 Provider、模型、Base URL 和 API Key。

- Base URL 只有主机路径时，myterm 会按 OpenAI 兼容约定补充 `/v1`。
- API Key 写入系统凭据库，普通配置只保存凭据引用。
- 使用测试按钮确认模型列表和聊天端点可用。
- 不要把 API Key 写入 Skill、MCP 参数、快捷命令、日志或截图。

## Agent 基本流程

在 Agent 输入框描述目标，而不是只输入一条命令。Agent 会循环执行以下过程：

```text
理解任务 -> 选择工具 -> 请求审批或执行 -> 读取结果 -> 继续判断 -> 最终答复
```

执行时间线会显示模型决策、工具、参数摘要、审批状态、stdout、stderr、结果和最终答复。任务会写入本地 SQLite，关闭面板或重新打开应用后仍可查询历史。

- `Enter` 提交任务，`Shift+Enter` 在任务中插入换行；中文输入法正在组词时按 `Enter` 不会误提交。
- 输入区顶部有水平拖柄。向上拖动可扩大输入区，向下拖动可恢复，最大不超过 Agent 面板高度的一半。
- 聚焦拖柄后可用 `↑`/`↓` 逐级调整，`Home` 恢复最小高度，`End` 扩大到允许的最大高度。
- Agent 标题栏的“新对话”会清空当前时间线和输入框，但不会删除已经持久化的任务历史；任务运行期间该按钮禁用，避免把活动 Turn 与新会话混合。
- “任务历史”展开后使用独立边框、背景和阴影。选择历史任务只切换查看内容；需要继续新的排查时，先点击“新对话”。

### 推荐任务写法

- 说明目标，例如“检查服务器磁盘压力并找出增长最快的日志目录”。
- 指明限制，例如“只读，不要修改文件或重启服务”。
- 指明输出，例如“给出证据、风险和建议命令”。
- 涉及生产或 root 时，拆分为排查和变更两个任务。

## Agent 权限

### 只读

只允许被策略明确识别为读取的工具或命令自动执行。语法不完整、包含替换、重定向或副作用时会升级为审批或拒绝。适合首次排查和生产检查。

### 用户确认

默认模式。有副作用的工具会显示工具名称、参数摘要和风险，用户批准后才执行。拒绝不会执行命令，任务可根据拒绝结果调整方案。

### 完全授权

硬拒绝规则之外的工具调用不再弹窗确认，适合明确承担当前任务风险的场景。`rm -rf /`、格式化磁盘、关闭系统等硬拒绝命令仍然不会自动放行。

### 硬拒绝

危险破坏命令由核心策略拒绝。Prompt、Skill、Hooks 和 MCP 都不能降低此策略，也不能绕过输出上限、审计和脱敏。

## Agent 内置工具

- `session_catalog`：按名称、分组、主机或用户查找已保存服务器，返回每个服务器的实时状态和最近一次 SSH 连接诊断；不会返回凭据。
- `session_info`：读取活动会话和服务器信息，也可以传入 `session_id`、`profile_id` 或 `profile_name` 查询非活动会话或已保存服务器。
- `terminal_context`：按 offset 读取终端 transcript，并返回活动 xterm 最近同步的可见屏幕、光标行、光标前内容和更新时间。
- `terminal_send`：向交互终端发送输入；可传入 `session_id` 指定非活动 SSH 会话。默认 `input_mode=complete_line`，参数 `command` 表示完整目标命令，宿主根据光标前内容只发送缺失后缀；`raw` 只用于确认、分页键或其他交互输入。
- `remote_exec`：通过独立 SSH exec channel 运行结构化命令；可传入 `session_id` 指定目标会话。
- `host_facts`：读取系统、CPU、内存、磁盘和网络等主机事实。
- `list_directory`：列出本地或远程目录。
- `file_stat`：读取文件元数据。
- `file_read`：读取受限大小的 UTF-8 文件。
- `file_search`：在限定目录和结果数量内搜索文本。
- `file_write`：原子写入文件并进行校验。
- `file_patch`：基于哈希锁修改已知内容并读回验证。
- `job_status`、`job_output`、`job_cancel`：管理后台执行任务。

终端上下文、主机事实、Runbook、SFTP 和文件工具同样支持可选 `session_id`。Agent 应先用
`session_catalog` 找到用户所说的环境，再把返回的 `session_id` 传给后续工具；没有实时会话时，
目录中的状态和诊断只能说明已保存配置或最近一次失败，不能当作主机当前可达性的证明。

结构化命令会分别记录 stdout 和 stderr，并保存退出码、信号、超时、取消或连接断开状态。大输出使用受限 artifact 和首尾预览，防止界面与模型上下文无限增长。

对于会自动补齐输入的交换机、存储或业务 CLI，Agent 必须先读取 `terminal_context`。如果终端已经显示 `show system`，目标命令为 `show system general`，宿主只发送 ` general` 和回车；如果现场是另一条不相容的命令，工具会原样返回当前光标行并停止写入，不会猜测、清行或继续拼接。没有前端 xterm 的后台 SSH 会话没有人工输入竞争，仍可发送完整命令。

## 后台 Job

耗时命令可使用后台模式运行。工具返回 Job ID 后，Agent 或用户可继续查询状态、按偏移读取输出或取消。

- 任务存在活动 Job 时不会提前生成最终答复。
- 应用异常退出后，未完成 Job 会标记为丢失，不会假装成功。
- 取消会传播到 SSH channel，并写入最终状态和审计事件。

## Skill

在 Agent 设置的 Skill 页面添加本地目录。myterm 会在受限深度、数量和大小范围内发现 `SKILL.md`。

- 先检查名称、描述、路径和内容哈希，再选择是否启用。
- 启用的 Skill 按任务需要加载，不会全部永久塞入上下文。
- Skill 是模型指导文本，不会获得高于用户所选权限的能力。
- 修改 `SKILL.md` 后重新发现以更新哈希和内容。

## MCP

MCP 支持 `stdio` 和 `streamable-http` 两种传输。添加服务器时先选择传输类型：stdio 配置命令、参数和工作目录；streamable-http 配置 MCP URL 和可选请求头（例如 `Authorization: Bearer ...`），然后先执行连接测试。

- 测试成功后会显示工具数量；点击“查看详情”可展开每个工具的完整名称、说明、所属服务器、Transport 和 Input Schema，也可复制完整 JSON 结果。
- Agent 调用 MCP 工具时仍经过统一权限、取消、输出限制和审计管线；两种传输对 Agent 暴露相同的工具目录和调用接口。
- 工具超过 48 个时，Agent 先搜索目录再显式调用，避免上下文膨胀。
- 不要在普通命令参数中直接写密钥；优先使用受控环境或系统凭据方案。

配置文件中的 HTTP MCP 形态如下（请求头可按服务要求填写，值不会出现在 Agent 工具参数摘要中）：

```json
{
  "id": "ops-mcp",
  "name": "运维 MCP",
  "transport": "streamable_http",
  "command": "",
  "args": [],
  "cwd": null,
  "url": "https://mcp.example.com/mcp",
  "headers": [
    { "name": "Authorization", "value": "Bearer <token>" }
  ],
  "enabled": true
}
```

### Agent 系统 Prompt 与 MCP 能力发现

`dsh-codex-agent` 使用内置版本化系统 Prompt。AI 服务设置里的 System Prompt 会作为附加任务指令，不会替换 Agent 的核心规则。核心规则包括证据优先、完整读取长输出、目标会话确认、权限边界、Skill/MCP 不得绕过策略，以及不确定时不能猜测。

MCP 能力不是写死在 Prompt 中。每次 Agent 任务启动时，myterm 会连接已启用的 MCP 服务器并发现工具；工具名称、说明和 JSON Schema 会作为当前运行时工具目录提供给模型。工具目录为空时，Agent 不得虚构 MCP 能力；工具目录较大时，Agent 先使用 `mcp_tool_search`，再用搜索结果中的准确服务器和工具调用 `mcp_tool_call`。当前运行时不默认假设 MCP Resources 或 Prompts 存在，只有实际暴露并注册的能力才可使用。

## 远端 CLI 与 REST 操作

myterm 所说的 CLI 和 REST 能力，主要指 Agent 在远程 SSH 环境中执行运维命令和 HTTP 请求，不是让 myterm 自身成为 CLI 或 REST 服务。

- 远端 CLI 使用 `remote_exec` 运行 `systemctl`、`journalctl`、`docker`、`kubectl`、包管理器和业务命令，并分别记录退出码、stdout、stderr、超时和取消结果。
- 当前可以通过 `remote_exec` 使用 `curl` 或 `httpie`。不要把 token 写入命令行、快捷命令或 Task 文本。
- 后续的 `remote_http_request` 会从指定 SSH 主机发起结构化 HTTP 请求，明确记录网络执行来源、状态码、TLS 验证、耗时和脱敏结果。
- 非幂等 POST 不自动重试；需要凭据时只引用系统凭据库，由工具在受控位置注入。

`0.6.3` 已删除早期实现的本机 Agent CLI 和 loopback REST。启动 myterm 始终进入桌面应用；当前也不会监听 Agent HTTP 端口。

## 多 SSH 与 OS 安装规划

当前 Agent Task 仍以单个活动 SSH 目标为默认上下文，但内置 Multi-SSH Coordinator 已支持通过 `session_catalog` 查找非活动或仅保存的服务器，并用 `session_connect` 自动启动或复用 SSH，再将明确的 `session_id` 传给后续工具。第一版跨目标协同默认为串行：完成并验证 A 后再操作 B。

OS 安装不会通过一条 SSH 命令直接执行。计划流程是：

```text
创建安装 Task -> 加载 OS 安装 Skill -> 只读盘点 -> 生成并校验 plan
-> 两阶段审批 -> provisioning 控制面执行 -> 观察重启/安装
-> 重建 SSH 信任 -> 后置验收
```

Skill 负责安装流程、模板和参数检查；真正的系统盘、启动项、电源和介质操作必须通过受策略保护的 provisioning 工具，并由虚拟化平台、云 API、MAAS 或 Redfish/BMC 控制。第一版只计划在隔离虚拟机上支持 Ubuntu Server Autoinstall，不支持生产物理机无人审批重装。详细方案见仓库中的 `docs/multi-ssh-os-installation-plan.md`。

## 数据与安全

- 普通配置位于用户配置目录，采用原子替换写入。
- 密码、私钥口令和 AI API Key 位于 Windows 凭据库。
- Agent 任务、事件和审计位于本地 SQLite。
- 敏感 JSON 字段和已知密钥会在持久化和 UI 分发前脱敏。
- 不要在问题报告、截图或日志中包含真实密码、Key 或私钥。
- 删除服务器时确认不再需要其凭据；升级安装会保留配置和凭据。

## 安装与升级

运行 NSIS 安装器即可安装到当前用户目录并创建桌面快捷方式。安装新版本时会调用旧版卸载流程、清理已验证的旧安装目录并安装新文件，同时保留用户配置和系统凭据。

便携 ZIP 包含 `myterm.exe` 和 `portable.flag`。便携模式的配置位置与普通安装不同，移动目录前应先退出程序。

## 常见问题

### 点击服务器无法连接

检查主机、端口、用户名、网络和认证方式。编辑配置时重新测试密码或私钥，确认服务器允许对应认证。已保存密码异常时可更新凭据后重新连接。

### 标签显示连接中但终端没有响应

等待认证完成并查看连接错误。确认服务器 shell 可以启动，终端类型可用，并检查防火墙或 SSH MaxSessions 限制。

### Agent 没有执行命令

检查活动会话、上下文工具开关、权限模式和审批区域。只读模式会阻止写操作；危险命令可能被硬拒绝。AI 服务不可用时先运行连接测试。

### MCP 连接失败

stdio 连接失败时，在系统终端中确认 MCP 命令可执行，再检查参数、工作目录和环境变量；stdio 服务器必须保持标准输入输出协议，不能把普通日志混入协议输出。streamable-http 连接失败时，检查 URL、TLS、代理、请求头和服务端返回的 HTTP 状态/响应体。

### 快捷命令执行到了错误服务器

执行前查看活动标签、分屏焦点和工作区连接标识。生产环境应使用明显名称和环境标记，并优先启用用户确认模式。

### 界面内存高于预期

原生 Agent 内核保持轻量，但 WebView2 使用多个进程。关闭不使用的会话和窗口可以减少资源占用；完整进程组低于 80 MiB 的目标仍在持续优化。

## 第一版边界

当前不提供复杂并行多 SSH 编排、结构化远端 HTTP、Skill 驱动 OS 安装、复杂多 Agent、长期记忆、任务编排平台和云端 Skill 市场。对于高风险生产变更和 OS 重装，myterm 应作为具备审批和审计的执行辅助工具，而不是替代资产系统、变更流程、备份和人工复核。
