# myterm v0.15.5 内网部署和验收

将本说明和 `myterm-intranet-upgrade-0.14.3-to-0.15.5.zip` 交给能够访问内网更新服务器的 Agent。客户端仅需在 Remote Ops 的「设置 → 更新」点击一次「检查并更新」。安装或升级后直接在「网页」输入网址即可，也可以让 Agent 调用 `remote_browser_open`。

## 部署到已有的 HTTP/HTTPS 更新源

1. 在暂存目录用 `Get-FileHash -Algorithm SHA256 -LiteralPath .\myterm-intranet-upgrade-0.14.3-to-0.15.5.zip` 核对随包 SHA256 文件，然后解压 ZIP。备份服务器现有的更新清单。
2. 先把 `stable/v0.15.5/` 的完整目录上传到内网更新目录，再发布 `stable/latest.json`。从客户端网络下载其中指向的 tgz 并核对 SHA256。v0.15.x 客户端若已使用此稳定入口，点击一次即可直接升级。
3. 仍有 v0.14.0 或 v0.14.1 时，在旧电脑正在使用的根入口先上传小于 64 MiB 的 v0.14.3 过渡包及校验文件，最后发布 ZIP 根目录的 `latest.json`。确认根清单公告 v0.14.3，且 `stable/v0.15.5/latest.json` 公告 v0.15.5。旧电脑的一次更新会自动安装过渡包和完整包。保留版本目录供稍后上线的电脑使用。
4. 正在执行上批 v0.14.2 迁移的客户端需要原根清单及 `stable/v0.15.4/`。让这批已启动的迁移完成后再切换根清单，保留其版本文件。已经是 v0.15.x 且仍指向过渡包根入口的客户端，在设置中将更新源改为同一站点的 `stable/latest.json`。全部旧配置完成迁移后，可恢复让根入口公告稳定版本；此时从根目录解析的资源路径应包含前缀 `stable/`。

## 客户端验收

- 在「设置 → 更新」确认「当前运行」和「已安装」均为 v0.15.5，已有环境仍可见。首次安装也可直接使用 `stable/v0.15.5/dsh-remote-ops-v0.15.5.tgz`。
- 切换到「网页」，输入这台电脑能访问的内网地址，点击「打开网页」，核对标题或页面内容。Agent 同样可以直接要求“打开这个内网地址”。首次打开会等待插件准备好随包 Chromium，用户无需操作安装向导。
- Windows x64 缓存位于当前用户的 `%LOCALAPPDATA%\myterm\cr`。以后打开新浏览器时会检查缓存，损坏的文件由插件从安装包恢复。若「设置 → 网页」显示失败原因，可点击「重试离线修复」。Linux x64 需具备 Chromium 所需的系统动态库。
- 录入升级前后版本、目标网页标题、是否手动安装浏览器。独立窗口沿用用户设置的本机引擎；选择专用完整版 Chromium 时才需要单独准备它。
