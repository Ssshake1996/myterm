# Telnet 终端使用指南

## 保存与连接

1. 打开 Remote Ops → 环境 → **SSH / Telnet** → **+ 环境**。
2. 连接协议选 **Telnet**，填写地址与端口（默认 23），按设备选择登录方式。
3. 需要自动登录时，在环境中保存密码。密码由 DSH credentials 保存，环境文件只保存引用。
4. 保存后点击 **测试**，查看连接和登录提示符结果；点击 **进入**打开可见终端。测试会建立并关闭一条临时连接。

| 登录方式 | 行为 |
| --- | --- |
| 在终端中登录 | 显示设备提示，由用户或 Agent 输入；测试仅确认 TCP 可连接，登录仍为未确认 |
| 用户名和密码 | 等待用户名、密码提示，各发送一次保存的凭据 |
| 仅密码 | 等待密码提示并发送一次密码，用户名可留空 |
| 无需登录 | 不提交凭据，等待设备的就绪提示符 |

**Telnet 是明文连接**，请使用适合该设备的可信网络。SSH 环境继续使用加密连接和主机指纹校验。

## 日常操作

用户和 Agent 在同一个终端中输入、读取回显，无需切换控制权。Telnet 沿用多标签、左右滚动、黄绿灰状态、搜索、命令显示和日志导出。标签的黄色登录提示表示连接已建立但登录尚未确认；绿色只表示连接及提示符就绪，不表示上一条命令成功。

“全部关闭”关闭当前对话的 SSH 和 Telnet 标签，保留本地 CMD、其他对话和已保存环境。断线不自动重放命令。终端日志可单独导出或将当前对话的全部日志打包。

自动登录失败、再次索要凭据或超时后停止提交，保留回显供检查。自动登录密码的原样回显会在进入可读输出和日志前脱敏；手动输入和设备自身输出仍需用户检查，导出前确认内容适合分享。

## 设备兼容设置

展开 **连接、编码与登录提示符**：

- 编码：默认 UTF-8，中文旧设备可选 GB18030；同时应用于输入与输出。
- 回车换行：默认 CRLF，设备需要时选择 CR 或 LF。
- 提示符：使用正则表达式；留空采用内置规则。默认识别 `login:`／`username:`、`password:`，以及以 `>`、`#`、`$` 结束的一行。特殊提示符可写成 `(?:^|[\r\n])SW-01>\s*$`。
- 终端尺寸：沿用环境默认尺寸与总设置。仅在设备接受 NAWS 协商时发送尺寸；设备可能不采用该尺寸。

文件工作区选择 SSH/SFTP 环境。Telnet 的命令在可见终端内运行，依据提示符和实际业务回显核实结果，不返回独立的进程退出码。

## 让 Agent 操作

可以直接说：

> 使用已保存的“实验交换机 Telnet”环境。先读取登录和设备提示符，执行 `show version`，核对返回内容，再导出本次终端日志。不要修改设备配置。

工具流程：`remote_environment_list` → `remote_terminal_open` → `remote_terminal_read`。确认返回的 `login.state` 为 `ready` 后，使用同一个 `sessionId` 调用 `remote_terminal_send/read/script`；手动登录和按键使用 `remote_terminal_input`。

自动登录期间只读取，不重复打开连接或提交密码。`manual` 表示需要在终端完成登录，`failed` 表示检查 `login.code/message` 和回显后再处理。`inferred_idle`、超时和提示符匹配都不能单独证明命令成功。

导出用 `remote_terminal_logs` 和 `remote_terminal_log_export`；`{ "all": true, "format": "zip" }` 打包当前对话可见日志，返回下载地址及 SHA256。无需 Agent 另写压缩命令。安装插件后，随包 `remote-ops-environments` 和 `remote-ops-terminal-logs` skill 提供这些说明。
