# 01 产品规格(MVP)

## 一句话定义

**mycode** 是一个运行在终端里的 AI 编程助手:用户用自然语言描述任务,它通过读写文件、执行命令来完成任务,期间所有危险操作需要用户确认。

## 目标用户与场景

开发者在自己的代码仓库根目录运行 `mycode`,然后:

- "帮我看看 `src/parser.ts` 里为什么空字符串会报错,修掉它"
- "给 `utils/date.ts` 里的所有函数补上单元测试"
- "这个仓库的构建流程是怎样的?"

## MVP 用户故事(全部必须满足)

| # | 故事 | 验收标准 |
|---|---|---|
| U1 | 我在仓库根目录运行 `mycode`,进入交互式会话 | 显示提示符,可连续多轮对话 |
| U2 | 我提问代码问题,AI 能自己读文件、搜代码后回答 | AI 自主调用 read/grep/glob 工具,答案基于真实文件内容 |
| U3 | 我让 AI 修改代码,它展示要做的修改并等我确认 | 写/改文件前打印 diff,用户按 y/n 决定 |
| U4 | AI 可以执行命令(跑测试、装依赖),执行前需我确认 | bash 工具执行前展示完整命令,等待确认 |
| U5 | AI 的回复是流式输出的 | 文本逐段出现,不是等全部生成完才显示 |
| U6 | 我可以用 `mycode --continue` 继续上一次会话 | 恢复完整历史消息,上下文连续 |
| U7 | 我可以随时 Ctrl+C 中断 AI 当前操作而不退出程序 | 中断当前生成/工具执行,回到输入提示符 |
| U8 | 我可以用 `--readonly` 启动一个只读会话 | 该模式下所有写操作和命令执行被拒绝 |

## MVP 功能边界

### 做

- 单一 LLM Provider:**Anthropic API**(但接口设计必须支持未来扩展,见架构文档)
- 6 个内置工具:`read_file`、`write_file`、`edit_file`、`bash`、`grep`、`glob`
- 三种权限模式:`confirm`(默认,写/执行需确认)、`readonly`(只读)、`yolo`(全自动,需显式 `--yolo`)
- 会话持久化到本地磁盘(JSON 文件)
- 纯文本流式 REPL(非全屏 TUI)
- 上下文超限时的简单截断策略(保留 system + 最近 N 轮)

### 明确不做(MVP 之后再说)

- ❌ TUI 全屏界面(M7 再做)
- ❌ 多 Provider(OpenAI、本地模型等)
- ❌ Client/Server 架构拆分、桌面端、IDE 插件
- ❌ LSP 集成、MCP 协议
- ❌ 子 Agent、plan/build 双 Agent 切换
- ❌ 上下文智能摘要压缩(MVP 只做粗暴截断)
- ❌ 图片/多模态输入
- ❌ 安装脚本、发包、自动更新

## 命令行接口

```
mycode                    # 新会话,confirm 模式
mycode --continue         # 继续最近一次会话
mycode --session <id>     # 继续指定会话
mycode --readonly         # 只读模式
mycode --yolo             # 全自动模式(不询问确认)
mycode --model <name>     # 指定模型,默认 claude-sonnet-4-5
mycode -p "一句话任务"     # 非交互模式:执行单个任务后退出(方便脚本化和测试)
```

配置来源优先级:命令行参数 > 环境变量(`ANTHROPIC_API_KEY`、`MYCODE_MODEL`)> 默认值。

## 非功能要求

- **安全**:confirm 模式下,任何文件写入和命令执行必须先经用户确认;工具不得访问仓库目录之外的路径(bash 除外,因其本身需确认)。
- **可观测**:`--debug` 时把每次 LLM 请求/响应摘要写入 `~/.mycode/logs/`。
- **健壮**:API 报错(限流、断网)要有指数退避重试(最多 3 次);任何工具执行失败都不能让进程崩溃,错误作为工具结果回传给模型。
- **成本可见**:每轮结束后打印本轮 token 用量;会话累计用量存入会话文件。
